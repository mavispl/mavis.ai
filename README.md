# AI Engineering Course

A four-week course on generative AI and agentic systems, generated by a staged
pipeline and audited before it ships. Every lesson carries its sources and a
verification date; every decision has a written spec.

## Layout

| Path | What it holds |
|---|---|
| `content/` | The course itself — lessons, wiki, gotchas, tools, recipes, labs (MDX) |
| `spec/` | Decisions (ADRs), the design system, the curriculum map and backlog |
| `research/` | Stage 3 output: dated sources per module |
| `audit/` | Stage 5 output: one directory per run, findings and report |
| `log/` | One JSONL record per unit of work, per pipeline stage |
| `.claude/` | The pipeline: authoring and orchestration skills, audit subagents |
| `scripts/` | Map builder, generators, and the automated audit passes |

## The pipeline

```
Stage 0  Harvest    reference material          → spec/curriculum/
Stage 1  Design     design system               → spec/design/   ← acceptance gate
Stage 2  Map        agenda → 107 lesson nodes   → spec/curriculum/map.json
Stage 3  Research   sources, dated              → research/<module>/sources.json
Stage 4  Author     lessons, wiki, gotchas      → content/
Stage 5  Audit      five passes                 → audit/<run-id>/
Stage 6  Build      export + index + deploy     → out/
```

Stage 4 is gated on the design system being accepted — a token change after 107
pages exist is a 107-page re-review.

## Commands

```bash
pnpm install
pnpm content        # compile + validate content against the schema
pnpm build          # velite → next build → pagefind index
pnpm typecheck
pnpm audit:all      # schema + graph + design/a11y, one combined report
pnpm map            # regenerate the curriculum map from the agenda
```

Serve the built site with any static server pointed at `out/`.

## How content is validated

`velite.config.ts` is the contract. The build **fails** if a lesson with
`volatility: medium` or `high` has no sources, if a published lesson has no check
for understanding, or if an id does not match its module. Everything a per-file
schema cannot see — agenda coverage, freshness decay, dead cross-links, contrast
floors — is checked by `pnpm audit:all`.

Two passes cannot be automated and run as subagents: the **fact** pass re-fetches
every cited URL and checks the claims still hold, and the **pedagogy** pass checks
each page actually serves the audiences it claims. The combined report names them
as outstanding rather than omitting them.

## Reading it

Six sections: a landing page, a sequenced crash course, the full deep dive, an
applied agents section with recipes, an A–Z wiki, and tools and setup with the
gotchas catalogue. A persona switch re-layers every lesson for juniors through
CTOs — it changes what is expanded, never what exists.
