title: Don't parse free-form model output with a regex
slug: free-text-parsing
category: Architecture & Integration
severity: medium
whatGoesWrong: >
  A parser works on every example during development and fails on a small percentage of
  production inputs. It gets reported as the AI feature being "flaky" rather than as a
  design error, so the fix attempted is prompt tweaking, which does not converge.
whyItHappens: >
  A prompt asking for a specific format is a request the model usually honours, not a
  guarantee. A preamble, a fenced code block, a trailing comma or an extra explanatory
  sentence all break the parser — and these appear more often on unusual inputs, which
  is exactly where correctness matters most.
howToDetect: >
  Look for prompts containing phrases like "respond only with JSON" or "output a
  comma-separated list" whose result is consumed by code. Then test with input that
  lacks the requested information entirely.
fix: >
  Use structured outputs so the schema constrains generation rather than describing it.
  Design the schema so absence is expressible — an optional field or an explicit
  not-found variant — otherwise a required field forces the model to invent a value.
