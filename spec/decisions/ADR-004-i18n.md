# ADR-004: English first, Polish structurally ready

- **Status:** accepted
- **Date:** 2026-09-04
- **Stage:** 1 — Foundation

## Context
The reference site ships English and Polish. Generating and fact-auditing both
doubles Stage 3–5 cost before the pipeline has proved itself once.

`next.config` `i18n` does not work with `output: 'export'`, so locale routing must be
a route segment if it is wanted at all.

## Decision
Ship English. Keep Polish reachable without restructuring:

- All UI strings live in `lib/i18n.ts` behind a `t()` lookup, never inline in JSX.
- Content ids (`w1.m01.b02`) are locale-independent, so a Polish lesson is a sibling
  file, not a new id space.
- `content/<locale>/` is the intended future shape; today `content/` is implicitly `en`.
- A `translate` stage slots between Author and Audit when Polish is commissioned.

## Consequences
- No `/en/` prefix in v1 URLs; adding Polish later introduces `/pl/` and leaves
  English paths untouched.
- UI strings must go through `t()` from day one. A hard-coded string in a component
  is a bug, and the audit flags it.
